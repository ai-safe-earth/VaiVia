# Phase 10 — Route factory v2 (drafted 2026-08-28; partly superseded 2026-09-02)

**Phase 12 supersedes this phase as catalogue generation.** F0 (recipe registry, labels, delete-by-recipe), F3 (short loops) and F4 (summit out-and-back) are not built: an on-demand planner draws the short loop or the summit route when asked, from the same rules, and there is no set to label or delete. What survives, relocated: F1's connectivity invariant and `urban_run_max_m`, and F2's `mini_loop` / `spur` / `parallel_go_and_back` rules become **planner invariants** in the shared package (Phase 12 slice 2; decision 1 in `docs/route-design.md` — they are what replaces the QGIS review for a route a user sees seconds after asking). F5 *sentiero* becomes a planner theme (a spine discount on the pack's cost columns) after slice 4. F6 urban areas and F7's `paved()` classification feed the pack (`edge_urban_m`, surface codes) and stay useful as pipeline work. The recipe and review tables below are kept as the record of the rules and tolerances; read them as planner constraints, not as a factory.

v1, in the code (`pipeline/draw/`): six families are six `draw.generate` invocations (`--shape` × `--activity`); persistence replaces per `(activity, shape)` and ignores `--region` (a Bergamo rerun deletes Lecco); a run's parameters live in `provenance.build_run` under its `run_id`, but nothing on the route row survives across runs to name the set that drew it; the only gate is `_rejected()` over `Assembled` scalars, so a mini-loop (distinct edges, retrace 0) and a go-and-back on a parallel street (different edge ids) both pass; the same-ground fold is counted only in aggregate (`kept − routes`, `generate.py:712-716`) — not per recipe, and not which row absorbed the candidate; `assemble.concatenate` emits a jumping line on a hole while `draw/emit.py` hard-codes `pieces=1`. Phase 7's P7 (custom routes) and P8 (direction documents) stay open beside this phase.

Locked (owner, 2026-08-28): five parametrised kinds; every route labelled with the recipe that built it so a bad set deletes wholesale; a review stage that rejects or modifies candidates, rules open; urban areas as polygons. No new `shape`/`kind` enum value and no schema release: `provenance.generation` is open by design (`route-document.schema.json`), `kind` stays `generated` (`export/document.py::PUBLISHED_KINDS`).

`sentiero` mechanics: spine = the relation's edges in `source_map.edge_route` ordered by `(member_index, piece_index)`, longest piece of the `ST_LineMerge` (`qa.v_route.pieces`). `edges_sql()` takes `{edge_id: factor}` (today one `penalised` set × 3.0): spine edges discounted, so the router prefers the sentiero without being forced across a gap; a `-1` arc is never resurrected; the fixed-template-plus-integer-ids rule stays — a factor is a float literal, never text. `spine_share` = metres on spine edges / total. `identity.ref` is None today and `name` only for destination rows; sentiero fills both from the relation, `osm_relation_id` stays null, `rel_id` under `generation.spine` — the document is drawn over the relation, it is not the relation. Counts: relations attempted / drawn / rejected by reason.

## The review stage — candidate rules (OPEN until built)

| rule | detects (walked sequence) | verdict | tolerance |
|---|---|---|---|
| `mini_loop` | the walk returns to a vertex visited < L m earlier | **modify**: excise `[i+1..j]`; both ends are one vertex so connectivity holds by construction | L from `--review-measure` |
| `parallel_go_and_back` | sub-walk a→b in urban fabric, crow(a,b) < d, walked ≫ crow, thin enclosed area | **detect-only** in F2; **reject** once the distribution is read; a re-routing repair is a later item | d, t |
| `spur` | palindromic sub-sequence inside a loop whose tip is not the destination and has no place within `PLACES_M` | **modify**: excise; exempt for `out_and_back` (the whole walk is the palindrome, `assemble.strict_return`) | max spur m |

Invariants for every rule:
- **Connectivity.** Consecutive walked end = next walked start. `WalkedEdge` gains `source`/`target` (`EDGE_DETAILS` already fetches them; `walked_sequence` discards them today). A violation raises before anything persists; `emit.py` derives `pieces` from the stored sequence.
- **Modify before mint.** A modification re-runs assemble and `_rejected`; rules are pure functions of (sequence, recipe), so the same ask draws the same route.
- **Every drop and fold counted.** `rejections` gains `review:<rule>`; fixes per rule; folds per recipe; all into `build_run.counts`. `--dry-run` prints, writes nothing. Score stays descriptive (`assemble.score`, `metadata-rules.md`).
- **Look before repairing.** A rule ships detect-only first; its verdict is switched on after the tolerance is read from the distribution and examples opened in QGIS.
