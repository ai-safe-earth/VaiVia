1 · Why this exists

docs/plan.md is additive: seven phases of checkboxes, each entry written when its work landed, correct sentence by sentence but never giving today's picture in one look. Two of its own framings are already history — the two-source data story (Trailforks is legally unavailable; the data is OSM throughout, plan.md "Context" still describes the old core) and Supabase as live auth (parked 2026-08-18, dev runs GATEWAY_DEV_NO_AUTH=true). This doc is the one-look version: what is actually running, which invariants carry it, and what genuinely remains. For per-phase details, the plan itself is the source — this doc cites, it does not restate.

Key takeaways

  • Phases 0–6 are built and verified; Phase 7 (the Bergamo refactor) is 5 of 8 items done.
  • Two plan framings are stale on purpose (additive doc): the Trailforks data story and live Supabase auth.
  • The one launch blocker that is not engineering: three credentials shared in plaintext during development must rotate before deploy.

3 · The three load-bearing invariants

Everything else in the plan can move; these three are the shape of the product. Each is enforced in code, not in prose.

3.1 · ① The gateway is the only public service

Auth, rate limits, origin control, quota pre-check, SSE proxy — and no business logic. The backend trusts only the gateway's shared-secret header and never parses a JWT; identity arrives as x-user-id. Verified by 40 gateway tests including real RSA-signed JWTs and claim-pinning negatives (docs/plan.md, Phase 3 and Phase 6).

3.2 · ②③ The LLM never sees or writes Cypher, and pays before it speaks

The model produces validated pydantic intents; Python composes them; named templates run with parameters only. Guard tests fail the build if a template mutates, traverses semantic edges in a path, or leaves a traversal unbounded — the boundary is a test, not a convention. Per-user daily cost caps are checked before every OpenAI call, in the backend authoritatively and at the gateway as a pre-check.

3.3 · ④ The route document is the product; every tier is a reader

Curated geometry and metadata live in PostGIS; pipeline/export/route_documents.py:199 emits one schema-validated JSON + GeoJSON per route (pipeline/schemas/route-document.schema.json, pinned by contract fixtures in both suites); Neo4j, the API and the frontend read it and none may redefine a route. Route ids are geometry digests (vv2-<16hex>) so photos and favorites survive rebuilds — the social layer's foundation, paid for in advance.

Key takeaways

  • Each invariant has an enforcement point you can run: gateway tests, query-loader guards, schema-contract fixtures.
  • The intent vocabulary is the entire attack surface the model gets; everything else is Python's.
  • The document contract is why the catalogue could be regenerated (P4: 1,371 routes) without breaking a reader.

5 · What comes next + recommendations

  1. Rotate the three plaintext credentials before anything deploys. The handoff has carried this amber flag since the incident; no engineering item outranks it. Actionable today: new Neo4j/Postgres/OpenAI secrets, old ones revoked.
  2. Reload Neo4j from the P4 catalogue. Live Neo4j holds 627 routes, all generated; the catalogue holds 1,371 including 751 mapped ones users currently cannot be offered. One neo4j_load run, then a count assertion in the audit script so the lag cannot recur silently. (Found while writing the eval doc.)
  3. Update plan.md's stale framings. The "Context" section still motivates the two-source Trailforks graph and the LLM-boundary section cites backend/app/intents/schema.py, a path that has been backend/chat/intents.py since Phase 4 landed. Two small edits keep the plan trustworthy as the ratified reference.
  4. Decide the routing-geometry migration. docs/routing-engine.md decided for GraphHopper and nothing has moved; the comfort-weighted GDS path still serves. Either schedule the migration into Phase 7's tail or mark the decision superseded — a ratified-but-unacted decision is the most expensive kind of doc debt.
  5. The 5-trail fixture stub as the entire (:Trail) layer — accepted, because the catalogue is the coverage story and a real trail source (OSM route relations already flow into the catalogue as mapped routes) is Phase 8 material, blocked on nothing technical.
  6. Supabase auth parked while the stack runs GATEWAY_DEV_NO_AUTH — accepted, because the gateway refuses that flag in production and the auth path stays tested; re-activation is configuration, not code.
