1 · Why this exists

An eval audit (2026-08-26, using the evals-skills checklist) found that the chat pipeline measured its first two stages and not its third. Decomposition had a golden dataset (backend/fixtures/golden_questions.json) and retrieval had --graph, but the answer prose — the stage carrying the most safety-loaded rules in the system: never invent a trail, never write a link, never name trailforks.com — had zero checks. Nothing would have noticed the model drifting on those rules, because the one rule that had failed before (links, live smoke 2026-08-21) was patched by a production sanitizer that also silently hides any recurrence from observation.

Three smaller gaps rode along: the eval's check logic existed twice (a drifted copy in check_intents_live.py with no loop. support), the dataset had zero Italian phrasings for a product serving Lecco and Bergamo, and scores lived only as hand-written prose in handoff.md — where they were already stale (24/26 figures for a 34-entry dataset).

Key takeaways

  • Before this branch: decomposition and retrieval measured, answer stage unmeasured, scores unrecorded.
  • The production link-stripper made the answer stage look safe while hiding whether the model obeys.
  • Deliberately deferred: error analysis on real traces (pre-launch, dump_conversation covers it) and any LLM judge (no judges before error analysis).

3.3 · Decisions, and why

  • ①One checker, one dataset. check_intents_live.py's golden half moved into golden_questions.json (entries g35–g42) and its drifted local check() was deleted; the script keeps only the 7-payload adversarial gate (scripts/check_intents_live.py:20). Rejected: importing check_plan into it — after the move the gate needs only plan.is_clarify. Cost: the gate no longer double-covers natural phrasings, which the 50-entry dataset now owns.
  • ②Code checks only; no judge. Every answer rule that a regex or a set-membership test can decide is checked in code; faithfulness ("no invented facts") is not checked at all, stated in the docstring as deferred. Rejected: an LLM judge now — the audit's own rule is no judges before error analysis, and an unvalidated judge is worse than a named gap.
  • ③Pin ids, never names. expect_loops takes vv2-… ids (geometry digests, pipeline/ids.py) because scripts/name_routes.py rewrites names every run. Only g30 is pinned (fixtures/golden_questions.json:311): the catalogue holds no ≤15 km hike loop near Lecco (its hike loops run 18–21 km) and Bergamo's catalogue is not in Neo4j — both data facts the eval now makes visible instead of hiding behind an unpinnable expectation.
  • ④Grade the raw stream. The orchestrator pipes answers through strip_links_stream (chat/orchestrator.py:241), so an answer captured from orch.run() can never contain a link. The eval calls stream_answer directly: it measures whether the model obeys, keeping the check a drift canary rather than a test of the strip. Cost: the eval bypasses run()'s quota guard — acceptable, it is an operator script.
  • ⑤Grade against the view, not the results. Checks read _answer_view(results) — the top-5 prefix the model was shown — because judging coverage against the full result set would fail the model for rows it never saw.
  • ⑥The log is committed. eval_runs.jsonl is versioned with the prompts that produced each line (owner decision, 2026-08-27), so git log answers "what did this prompt change cost". Rejected: keeping scores in handoff.md prose — that is how they went stale.

3.4 · For a scalable system

  • Entries run sequentially; a 50-entry --graph --answers run takes ~5 minutes and ~110 OpenAI calls. Ceiling ≈ a few hundred entries; the upgrade is an asyncio.gather batch with a small semaphore — the harness has no shared mutable state to stop it.
  • Trail retrieval can never grow past 5: (:Trail) nodes come only from the fixture (ingestion/trailforks_ingest.py). This ceiling belongs to the data story, not to the eval; the catalogue (expect_loops) is the growable half.

3.5 · Security

  • The adversarial gate is the containment regression test: all 7 injection/out-of-scope payloads must compose to clarify, which runs no query. Re-verified 7/7 after the refactor and again after the P1 prompt change. Dataset entries g15, g33, g48 keep injections (one Italian, one mid-conversation) in the scored set too.
  • The eval needs OPENAI_API_KEY and a live Neo4j; it is a script, never CI — CI stays offline by construction and the checker functions have their own offline tests (tests/test_eval_golden_checks.py).

Key takeaways — P0

  • The eval certifies the production path because it is the production path, tapped at three points.
  • Dataset 34 → 50: dedupe from the live script, eight Italian entries, id-pinned catalogue loops.
  • What is deliberately not checked is written down (faithfulness → after error analysis), not implied.

4 · P1 What measuring changed, same day

4.1 · Goal

The first --answers run scored 34/44 and every failure was one rule: the prompt demanded every loop be called by name while also demanding brevity — with five loops and five trails in view, the model had to break one rule or the other. The fix relaxes the rule to what a walker needs, in prompt and checker together, and the re-run proves it: 42/44.

4.3 · Decisions, and why

  • ⓐRelax the rule, don't grade harder. Rejected: keeping the every-name rule and calling 34/44 a model deficiency — the rule itself was contradictory, and an eval that fails a model for obeying the neighbouring rule teaches nothing. Prompt and checker moved together in one commit (b9902bb) so the score line brackets exactly one semantic change.
  • ⓑWhether a mentioned name is exactly as given is judge territory. The code check is substring, case-insensitive (a destination route is named "To Monte X" and the prompt says to write "out and back to Monte X"). Verifying verbatim naming needs interpretation; deferred with the rest of the judge work.
  • ⓒThe out_and_back gap was found by counting, not by a failure. Writing this work's live counts showed 167 of 627 loaded routes carry a shape the prompt never described — the factory added it 2026-08-25 (pipeline/docs/metadata-rules.md, "The parametric factory") and the prompt was never told. The model had been improvising on a quarter of the catalogue. No eval caught this because no check can catch a shape the spec itself omits.

Key takeaways — P1

  • 34/44 → 42/44 from one rule change; the residual 2 fail the relaxed rule genuinely (no loop named at all).
  • Prompt and checker are one contract: they change in the same commit or the scores lie.
  • The first day of measurement paid for the harness twice — one contradiction, one silent spec gap.
